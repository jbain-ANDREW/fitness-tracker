- Calorie history chart: dual bars per day (orange food, green/red net), inter-day spacing, computed goal line ✅
- Meal section dividers: slightly grey for visibility ✅
- Workout: each pick (exercise, sets/reps/weight, notes) saves immediately instead of one final submit; menu rehydrates from saved state on load/date switch so a mid-session app-switch on phone doesn't lose progress; "Log Workout" button removed ✅
- Reverted the two July 17 "perf" commits (History tab's two-phase lazy weight/calorie loading, and the CacheService/read-consolidation changes behind it) — suspected cause of phone-only intermittent UI freezes that self-resolve after a while, not reproducible on desktop. History tab is back to one single load on open, no caching. Not root-caused for certain (see note below); revert chosen because it's the known-good state and the user prioritized reliability over the load-time win. Watch for whether freezes stop on phone. ✅ (reverted, not confirmed fixed yet)
- Weight chart: "Days back" dropdown's 90-day option replaced with "All time" — server (getHistoryPage) no longer truncates weight history to the requested window (food/activities still do, stays at 90 days). Chart's own x-axis label spacing already scales with point count, no change needed there. ✅
- Data load triggers reworked to fully on-demand: removed every automatic google.script.run call that fired on page open or tab switch (Log tab's initial load, History/Config/Meds/Workout/Inbox auto-fetch on first tab visit). Each pane now has an explicit Load/Refresh button instead; switching tabs just re-renders whatever was last fetched this session, no network call. Changing the date picker (Log tab, Workout tab) still auto-fetches that day's data since it's a deliberate action, not a background load. Writes were already refreshing their own pane's state from the write response (or via a follow-up call like loadMeds()/loadInbox()) — unchanged. Motivated by the unresolved phone-browser freezes noted above; this removes background loading entirely rather than trying to make it lighter/cached, so it should be easy to tell if the freezes were load-triggered. Not yet confirmed fixed on phone. ✅ (implemented, not confirmed fixed yet)
